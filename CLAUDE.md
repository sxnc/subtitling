# Subtitle Optimizer — agent instructions

**You (this Claude Code instance) are the optimizer.** No API keys, no external
model calls. You read the subtitle events, apply the optimization rules below
yourself, and use `optimize_subs.py` only as a deterministic parse/write helper
that guarantees timestamps and structure are never corrupted.

## Trigger

The main use: the user drops a subtitle file into the terminal (pasting its path)
and hits enter. **When the user's message is essentially just a filesystem path
(or several) ending in `.srt` or `.vtt`, with no other instruction, treat it as
a request to optimize that file — do it without asking for confirmation.**

Clean the pasted path first: strip surrounding quotes, un-escape backslash-escaped
spaces (`My\ Video.srt` → `My Video.srt`), expand `~`. If several paths are
pasted, process each.

## Procedure

1. **Set up the helper once.** If `.venv/` is absent in this project, create it:
   ```bash
   python3 -m venv .venv && .venv/bin/pip install -q -r requirements.txt
   ```
   Otherwise reuse it.

2. **Extract the events** as JSON:
   ```bash
   .venv/bin/python optimize_subs.py extract "<cleaned path>"
   ```
   You get `{"format", "count", "events": [{index, start, end, start_seconds,
   gap_before, text}, ...]}`. `gap_before` is the silence (seconds) before each
   event — use it for the dramatic-pause rule.

3. **Optimize the text yourself**, applying every rule in "Optimization rules"
   below. Produce a JSON array of `{"index": <int>, "text": "<optimized>"}` for
   the events you changed (unchanged events may be omitted). Keep `\n` for an
   intentional in-event line break. **Never change indices, never add or remove
   events.** For a long file, work through it in order in batches, keeping the
   surrounding lines in mind for context — but keep every index exactly once.

4. **Write the edits to a temp file and apply them** (avoids shell-escaping a
   large JSON blob), closing small gaps in the same pass:
   ```bash
   .venv/bin/python optimize_subs.py apply "<cleaned path>" /tmp/edits.json --close-gaps
   ```
   (or pipe via `-`). The helper re-attaches the original timestamps by index and
   writes `<name>_optimized.<ext>` beside the input. `--close-gaps` also runs the
   gap-closing rule below (tune the threshold with `--max-gap <seconds>`, default
   1.5). **If the source language is German, always add `--swiss`** — it enforces
   the eszett rule below across every event, including ones you did not edit. To
   close gaps without any text changes, use the standalone
   `close-gaps` subcommand:
   ```bash
   .venv/bin/python optimize_subs.py close-gaps "<cleaned path>" --max-gap 1.5
   ```

5. **Report** the output path and a one-line summary (format, event count, and
   the kinds of fixes you made).

## Optimization rules (apply these exactly)

- **Proofreading.** Silently detect the source language and edit only in that
  language — never translate. Fix spelling, grammar, typos, and punctuation.
  Preserve the original meaning, tone, register, and slang; do not formalize,
  censor, summarize, or add content.
- **Swiss Standard German (German-language files only).** Write *Schweizer
  Hochdeutsch*, not German-German orthography:
  - **No eszett, ever.** Every `ß` is written `ss` (`heisst`, `gross`, `weiss`,
    `Strasse`, `dreissig`), and a capital `ẞ` is `SS`. This holds in proper nouns
    and loanwords too. Passing `--swiss` to `apply` enforces this
    deterministically — write `ss` yourself anyway, and treat the flag as the
    safety net for events you did not touch.
  - **Quotation marks** are guillemets, «like this», with ‹single› ones nested
    inside — not the German „…“ pair.
  - **Thousands separator** is an apostrophe: `1'000`, `25'000 Tonnen`.
  - This is an *orthography* rule, not a vocabulary one. Do not swap the
    speaker's words for Helvetisms (or vice versa) and never render Swiss German
    dialect into standard German — that would be translating. Only the spelling
    conventions above change.

- **Semantic line breaking.** Keep words that belong together on the same line /
  within the same event: articles+nouns, adjectives+nouns, auxiliary+main verbs,
  prepositions+objects, multi-word names. Break at natural syntactic boundaries
  (after punctuation, before conjunctions), never mid-phrase.
- **Orphan word & punctuation control.** Never leave a single lonely word at the
  start or end of an event, UNLESS `gap_before` (or the gap after) is greater
  than ~1.5s, indicating a deliberate dramatic pause — then a lone word may
  stand. Redistribute text across the EXISTING events so each ideally ends on a
  natural punctuation break (comma, period, question mark) when timing allows.
- **Gap closing (deterministic, helper-driven).** Subtitles generated by STT
  often have lots of tiny gaps between consecutive events that make the text
  flicker. The `--close-gaps` flag (and the `close-gaps` subcommand) removes them
  by extending each event's END time forward to touch the next event's start,
  but ONLY when the gap is at or below the threshold (`--max-gap`, default 1.5s).
  Larger gaps — title cards, scene changes, deliberate dramatic pauses — are left
  intact. This only ever lengthens an event's on-screen time; it never moves a
  start, never shortens an event, and never creates an overlap. It is done by the
  helper, deterministically — never hand-edit timestamps to achieve it.
- **Strict timestamp preservation (absolute).** You only ever supply text keyed
  by index. You may move words between events that already exist, but never add,
  delete, or reorder events, and never hand-edit timestamps. The output event
  count must equal the input count; if an event ends up empty after
  redistribution, give it an empty string rather than dropping it. The one
  sanctioned timing change is helper-driven gap closing (above), which extends
  end times only.

## Notes

- Do not hand-edit the subtitle file directly — always go through
  `extract` → your optimization → `apply`, so structure and timing stay valid.
- The input file is never modified; a new `_optimized` file is written beside it.
